## 进入100条的通过门槛

1. **真实执行与数值。** 权重身份、精度定义和后端证据完整；量化投影按声明精度实际执行，无隐式 FP16 激活回退；原生mRoPE、完整视觉输入及FP16 KV保留。更改内核必须重新进行相应合成/真实层数值核验及固定输入完整模型回归。图模式必须有实际 capture/replay 证据，不能仅检查配置开关。
2. **稳定性与格式。** 20/20案例及全部真实请求记录完整；基础设施错误、非法动作/解析失败、输出截断均为0。任何失败保留原始输出与案例，禁止从分母删除。输出到512 token且 `finish_reason=length` 计截断；模型质量失败与HTTP/CUDA/OOM等基础设施失败分别标记。技术执行通过不代表质量通过。
3. **20条明显质量问题筛查。** 量化成功数不得比同条件新 FP16 少超过2/20；平均SPL下降不得超过0.10，即量化成功数≥FP16成功数−2且量化SPL≥FP16 SPL−0.10。FP16先满足自身工程/格式门槛。阈值只决定是否扩大复测，不是置信区间或质量等价结论。触发阈值后定位原因、修复并重测受影响20条，保留全部尝试。
4. **固定输入速度。** 在同服务条件、相同真实输入与相同返回token预算下重复测量，量化 HTTP P50 与 P95 各不得超过同条件新 FP16 的1.10倍。使用同一两图/九图输入、18/64 token四格；每格先2次预热，随后至少10次计时，全部组使用同样顺序/等待策略。若有系统漂移导致临界或不一致，隔离原因并重复匹配对照；不能选择有利慢基线。闭环P50/P95同时报告，但不同轨迹/输出长度不能替代固定输入速度门槛。

固定输入性能小测的强制输出长度仅用于隔离比较；闭环始终采用上表原512上限与自然结束规则。每个固定输入请求前可使用既有确认协议的1秒静置，计时从静置后开始，并明确这是测量条件。闭环沿用原真实调用节奏；不得把静置、模拟器渲染或排队动作零耗时混成HTTP模型延迟。运行协议冻结后不跨条件拼表。

## 统计与审计口径

成功必须为末步模型主动 STOP、无错误、距离<3m；错误回退STOP不算成功。SR分母固定20或100；SPL按该成功判定重算 `success × start_distance / max(start_distance, path_length)`，失败为0。不能直接使用含错误回退成功的 Habitat summary SR/SPL。

HTTP只汇总 `model_called is True` 的 `model_request_s`，排除每批2次预热与排队动作的0秒记录；报告真实调用数、总耗时、P50/P95、真实返回token与输入token。P95为全部真实请求样本的线性插值95百分位，不按案例中位数再次取分位。暖启动及尾部刷新请求单列，不进入正式统计。

prefill/decode分别记录CUDA事件区间；decode均值分母为实际前向次数，不能用返回token数替代。记录 capture/replay、每条请求与计时文件对应、模型实际输入长度及尾部前向。最后独立发送尾请求刷新上一条计时，并排除尾请求本身。首次输入哈希采集只在明确预热中进行；不能把每个新长度的 CPU 拷贝/SHA开销混入正式闭环请求。

显存保持整卡200ms采样峰值口径，并说明含桌面和预热、并非模型独占或瞬时精确峰值。新的服务/运行器/审计代码、模型、manifest、policy、环境配置、结果、逐步日志及计时文件保存SHA。比较表始终包括同条件FP16，形成1基线+8量化组；不支持或未通过组如实标记，禁止补造8组完成结果。

若20条之后实现、权重、提示、输入预算、生成策略、计时或统计口径改变，受影响的20条须重测。只有这些条件及源代码完全冻结且审计通过，才能把新20条作为同100条合法子集追加剩余80条，明确累计口径。历史结果保留，仅作历史参考。
